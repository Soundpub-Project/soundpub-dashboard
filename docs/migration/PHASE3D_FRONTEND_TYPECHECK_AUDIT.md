2. **P1 — new branding UI exceeds backend contract:** `BackendSettings.tsx:54` uploads `OTHER/settings` and stores returned object ID; `services/settings.ts:12` constructs `/api/v1/settings/public-media/<key>`. Final inspection saw concurrent changes adding settings category/size/authority support; `rg public-media backend/src` still found no route. Anonymous display remains unverified/incomplete; upload binding/attachment needs fresh contract verification after writer finishes. Keep branding controls unavailable until category authorization, binding and public serving exist. Inspected media contract remains PRIVATE-only; do not publish private object capabilities as workaround. No backend change made here.
3. **P2 — business Realtime remains active:** `DashboardLayout.tsx:64-97` always subscribes to `Soundpub.profiles` changes for own ID and child label IDs. `usesBackendReleases()` only short-circuits balance RPC, not subscription. Mounted dashboard still connects to Supabase Realtime with all backend flags. Minimal fix: skip subscription when users domain is backend; retain API profile refresh until financial refresh contract exists.
4. **P2 — branding validation has undefined ceiling:** `services/media.ts:22` size map lacks `OTHER`; indexing yields `undefined`, multiplied ceiling becomes `NaN`, so size check never rejects oversized branding images before whole-file hashing. Backend rejects category later, after memory cost. Minimal safe fix while unsupported: reject unknown category before `arrayBuffer()`; when supported, add explicit validated category ceiling. Existing four supported categories already have limits.
5. **P2 — current lint failures include introduced defects, while TS failures mostly predate migration.** Details below. A passing Vite build/static regex gate does not certify typecheck or app-wide zero Supabase traffic.

Keep expiry/interruption/error browser cases open; static tests are insufficient evidence.
