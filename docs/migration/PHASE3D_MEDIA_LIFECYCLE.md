# Phase 3D media lifecycle

`POST /api/v1/storage/uploads` validates category/resource binding, extension/MIME, category byte limit and SHA-256, checks live ownership/status, creates PENDING metadata and returns five-minute signed staging PUT with required headers. PUT bytes alone grant no business authority. `POST /api/v1/storage/uploads/:id/complete` rechecks live ownership/resource/state, expiry and byte length/content type/checksum/signature. Only verified snapshot copies into immutable final key, binds `*_media_id`, marks ACTIVE and audits. Previous active binding becomes REPLACED after successful verification; old bytes retained until deferred cleanup. Replayed staging PUT cannot overwrite final key. No transcoding, malware scanner or full file decoder: signature checks are format hints only.

`GET /api/v1/storage/objects/:id/download` demands current resource access, ACTIVE status and current foreign key binding; backend returns 60-second signed capability. `DELETE /api/v1/storage/objects/:id` and abort reject stale/foreign authority; resource state restricts release/track changes. Migration `0012` adds monotonic request order so overlapping transactions cannot mistake an earlier upload for a newer replacement based on `now()` timestamps. Async failures can leave staged/final bytes: `cleanup()` handles only known metadata-owned expired/failed/replaced/deleted objects; `reconcile()` reports missing/mismatched/unreferenced rows and unknown keys without deleting unknown/shared objects. Local CLI: `npm run media:reconcile`, `npm run media:cleanup` from `backend/` with isolated development environment. Cleanup must not precede signed capability expiration.

Release readiness uses active cover and each Track's active audio media binding in same submission transaction; payment/provider remain separately blocked. User/label/release/track displays must resolve private media through authorized backend endpoint; a relative `download` JSON URL is not an image source by itself. No one-year signed URL is canonical identity.

## Final branding lifecycle addendum

`OTHER/settings` is restricted to fixed settings resource `00000000-0000-4000-8000-0000000003d0` and image MIME types. Only current admin/superadmin may request or finalize. Completion verifies immutable bytes, atomically replaces active variant, binds the UUID into allowlisted application setting, and increments settings version. Anonymous `dashboard_logo_light`, `dashboard_logo_dark`, and `favicon` reads resolve only the current active matching variant and issue a short-lived signed redirect. Deletion clears only matching binding; cleanup recognizes settings references.
