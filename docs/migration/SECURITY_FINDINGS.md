- **C3 PASS:** production `user_roles` client DML revoked; SELECT retained. Management policy now requires admin, denies self-change, and prevents non-superadmin changes involving a superadmin target or role. Service role remains available. Isolated and live corrected assertions passed.

## High findings and qualifications

- H1: 56 live soundpub functions, 51 SECURITY DEFINER, all 51 owned by postgres; Pre-remediation 36 of 51 executable by anon; post-remediation 34 of 51 remain anon-executable. Two had no fixed search_path: cleanup_expired_tokens and cleanup_rate_limits. Both bodies use schema-qualified tables; missing search_path alone does not prove injection. After remediation cleanup_rate_limits no longer allows anonymous execution; cleanup_expired_tokens still needs body/ACL review. Many others include public in search_path: audit schema CREATE privileges before claiming writable-path exploit. Trigger-returning functions are not automatically callable as ordinary RPCs. Review each signature/body/ACL before revoke.
- H2: scan_orphan_artist_links is anon-executable SECURITY DEFINER; inspected body starts directly with data CTEs and returns names/UUID/business counts without actor gate. Do not execute and expose results. repair_orphan_artist_link also has anon EXECUTE but body explicitly requires admin/superadmin: distinguish broad grant from unauthorized mutation. Restrict both grants appropriately.
- H3: record_auth_audit has anon EXECUTE but body rejects NULL auth.uid(); anonymous audit write is NOT confirmed. Any authenticated actor supplies arbitrary action/target; actor derived server-side. Treat these records as untrusted client events unless action allowlist/target authorization enforce semantic integrity. Proxy-header trust also requires validation.
- H4: Deployed SSO validates RSA signature and exact issuer, conditional exp and optional azp, and requires client roles; no aud/email_verified check found. Existing profile lookup by email then magic-link session creates account-linking risk. Require issuer+subject mapping, mandatory typed expiry/client claims and verified-email conflict policy; identity provider configuration not independently inspected.
- H5: Users.tsx:230 stores original privileged session including refresh_token in sessionStorage during impersonation. Runtime impersonation does require superadmin. Browser compromise can expose privileged token; use short-lived scoped/revocable impersonation with audit. No token values read.
- H6: ProtectedRoute.tsx:82 only rejects mismatched truthy role; null-role UI fails open. This does not establish DB bypass. Backend must default-deny. Six-hour UI session expiry is not revocation; suspended user's issued JWT behavior remains untested.
- H7: Storage private media SELECT policy allows every authenticated host user to read all release-covers/track-audio/track-video objects. No Soundpub membership or row ownership predicate. Shared-host isolation fails at policy level. Eight storage policies total; no explicit client payout-proof/invoice/contract policy. Service-role access bypasses RLS. Private bucket alone is insufficient.
- H8: Backup metadata: two failed storage_backup_runs, zero storage_backup_log entries. Earlier there was no successful byte backup/restore proof; Phase 1 private archive/restore progress is tracked in BACKUP_REPORT.md. External storage and shared ownership remain blockers; see STORAGE_AUDIT.md.
- H9: Financial high-risk baseline remains unresolved here: runtime invoice creation checks release owner/label/admin, copyright invoice checks registration/payment owner. Read-before-create invoice idempotency and Xendit multi-step callback require concurrency/replay verification by financial/runtime workstream. No payment request sent. Schema provenance/deploy drift remain coordinator gates; this report does not certify all 14 historical differences unchanged.
