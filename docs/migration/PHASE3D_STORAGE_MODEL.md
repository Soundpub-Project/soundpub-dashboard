# Phase 3D storage model

`backend/migrations/0009_media.sql` adds private `soundpub.media_objects` (backend-only grants, no browser role grants); `0012_media_request_order.sql` adds monotonically allocated upload intent order. Primary metadata: UUID ID, `s3-dev` provider, bucket, object key, actor-derived owner, category/resource type/resource ID, `PRIVATE` visibility, MIME, byte size, SHA-256 checksum, lifecycle status, timestamps and short upload expiry. Typed foreign keys `profile_id`, `release_id`, `track_id` and active-binding uniqueness constrain association; application checks current resource authority under transaction locks. Canonical identity is UUID, never signed URL. Existing `storage_assets` remains Phase 2 generic foundation; new `media_objects` is resource-bound application layer.

Categories: USER_AVATAR, LABEL_LOGO, RELEASE_COVER, TRACK_AUDIO supported. OTHER is supported only for admin-controlled application branding on fixed settings resource `00000000-0000-4000-8000-0000000003d0`; COPYRIGHT_DOCUMENT and TAKEDOWN_DOCUMENT deliberately reject until case authorization exists. Objects remain private in storage. Anonymous branding uses three allowlisted same-origin endpoints that resolve current active settings bindings to short-lived signed redirects; no arbitrary ID/bucket/key access or anonymous bucket policy. Legacy `*_url` fields are compatibility display references; backend association is typed media identity and readiness checks active bindings, not URL presence. PostgreSQL metadata and dedicated local S3-compatible object store are separate systems; completion and cleanup reconcile rather than claim distributed transactions.

`soundpub.notifications`, `notification_reads`, `application_settings`, `user_settings` are also private-schema backend-only tables. Existing `audit_logs` has backend SELECT/INSERT, no browser grant and no read/write mutation route except constrained admin reads. RLS strategy: BACKEND_ONLY_RLS_OPTIONAL for private schema and app-only grants; current backend service re-checks live actor roles/status. If any table is later exposed to Supabase Data API, revoke exposure or add RLS before granting browser roles.

Production media and legacy GCS/Supabase objects are not imported. Dedicated local-only endpoints accepted; production credentials and shared bucket policy changes prohibited.
