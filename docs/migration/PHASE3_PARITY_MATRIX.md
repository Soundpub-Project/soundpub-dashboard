## Differences and concrete blockers

1. **Token and browser transport:** frontend token provider reads Supabase session access token, while bootstrap uses exact DEV_AUTH_TOKENS_JSON lookup. No token bridge is implemented or authorized. Local browser cross-origin Authorization preflight returned 404 with no Access-Control-Allow-Origin; Vite has no API proxy. Use synthetic identity integration and explicitly tested local transport, never paste a production token into mock mappings.
2. **Pagination and labels:** synthetic first page of 50 + non-null nextCursor produces exactly one frontend request and 50 returned rows. Parent name supplied by server becomes null when parent is outside that page. Local search/status/login-method filters and label selection therefore miss later users. Preserve current full-list UI behavior or provide complete pagination UI; do not report backend cursor support as adapter parity.
3. **Money DTO:** backend profile balance is exact decimal text. During refresh frontend BackendUser changed to number|string and Auth hook added Number conversion. Users list still passes decimal text through; no runtime DTO validation or safe precision ceiling established. Exact mock-fetch check observed a string. Keep authoritative decimal strings and test explicit presentation mapping, especially values outside safe JS integer range.
4. **Role transfer and provenance:** refreshed Users role endpoint blocks any supplied local-parent change, including first assignment; no parent write remains. Earlier static path clearing historical references was removed during concurrent work. Transfer confirmation, roster creation and historical royalty handling remain absent. DB/reference preservation proof still not executed here.
5. **Inactive behavior:** legacy UI describes inactive as still able to log in. Target denies inactive API principals. This conservative boundary is explicit in Phase2; retain it until product policy/fixtures resolve difference. Do not mark equivalent or remove protection to emulate insecure behavior.
6. **Partial-domain routing:** backend Users mode still leaves create/delete/password/impersonation/composer and unrelated pages on Supabase. No complete-domain or mixed-source mutation safety proof. Routing now uses centralized VITE_SOUNDPUB_BACKEND_DOMAINS membership with `users`, gated by `import.meta.env.DEV`; earlier VITE_BACKEND_USERS switch was replaced during review. No browser/build attestation performed.
